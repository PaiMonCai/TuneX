# ForwardX 代码复用登记（许可证与溯源）

> **状态：生效中。** 本文件是 ForwardX→TuneX 代码复用的**唯一台账**。任何从 ForwardX 复制/移植的代码都必须在这里登记一行。

## 1. 决定与授权

| 项 | 值 |
|---|---|
| 决定 | **直接复用 ForwardX 的代码与逻辑以加快开发速度** |
| 决定人 | 用户（本会话内直接指令） |
| 决定时间 | 2026-10-07（专项第 45 轮） |
| 授权范围 | **全部**（用户明确选择"直接复制代码，我接受 AGPL-3.0 后果"，并对"最想加速的目标"回答"全部"） |
| **Lead 已履行的告知义务** | 在动手前明确告知：ForwardX 是 **AGPL-3.0-only**；复制其代码会使**被复制部分（乃至整体）受 AGPL 约束**；若 TuneX 作为**网络服务**对外提供，AGPL 要求向使用者提供**完整对应源代码**；事后剥离成本高；且两栈不同（Node/Express/React vs Bun/Hono/Prisma/Next/Go），照搬会引入双范式。**用户知情后仍选择该口径。** |

**本决定改变了专项此前的一条硬约束**：`docs/agent/productization-harvest.md` 与各 recon 文档原写"ForwardX 仅作行为参考、clean-room、禁止复制代码或文案"。自本决定起，**该约束按用户授权放开**；但下列纪律**仍然有效**（它们不是许可问题，而是工程纪律）：
1. **参考目录仍不得进入 git**（`Forwardx(参考项目，不进入git提交）` 仍在 `.gitignore`）——只把**移植后的代码**提交进 TuneX 源码树。
2. **每一处复用都必须在本文件登记**（TuneX 文件 → ForwardX 源文件 → 复用范围 → 许可），并由 Lead 维护。
3. **每个被复用/移植的文件头部必须带来源与许可标注**（格式见 §2）。
4. **不得声称自研**：注释、PR、提交信息里不得把复用代码描述为原创；反过来也不得遗漏 AGPL 许可信息。
5. 复用代码**仍须通过本专项的全部门禁**（tsc / 单测 / 真机证据 / 三态与措辞纪律）——"照搬"不是"免检"。

## 2. 文件头标注格式（强制）

新增或修改的、含 ForwardX 来源代码的文件，头部必须含：

```
// Ported from ForwardX (AGPL-3.0-only): <forwardx 源文件相对路径>
// 复用范围：<逐字复制 / 改写适配 / 仅算法与结构>
// 许可：本文件含 AGPL-3.0-only 代码；分发/对外提供服务时须遵守其条款。
// 登记：docs/agent/forwardx-code-reuse.md
```

Go / TS / TSX 用 `//`，`.md` 用 HTML 注释或引用行；Dockerfile 用 `#`。

## 4. 需要保护的边界（复用不等于放弃判断）

以下边界即使复用代码也**不得**被绕过，因为它关系到 TuneX 自己的正确性（与许可无关）：
- **一次真相 / 读时派生**：ForwardX 有若干"进程内 Map 记状态""配置表存 lastSent"的写法（其通知/调度器里就有）。复用时**不得**把这类"第二份真相"搬进来；命中时应**只借它的产品逻辑，不借它的状态管理**，并在登记表里注明"改写适配"。
- **失败可见与诚实措辞**：ForwardX 有把失败只写 `console.warn` 的地方。复用其 UI/逻辑时，**不得**因此丢掉我们的账本/退避/`failure_reason` 呈现。
- **权限与作用域**：ForwardX 没有 workspace/tenant 概念。复制其服务端逻辑时**必须**接入我们的 workspace 作用域与权限内核，不得直接照搬其"全局单例"假设。
- **凭据治理**：不得把明文凭据处理方式照搬（如把 secret 放明文配置）。
