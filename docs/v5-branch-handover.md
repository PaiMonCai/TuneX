## 5. 并行协作沉淀下来的规则（都是踩出来的）

1. **提交用 `git commit -F - -- <显式路径>`，身份 `-c user.name/user.email` 与 `-F` 都写在 `--` 之前。**
   两个方向都要挡：`git show --stat` 挡得住"我的提交带走别人**未暂存**的文件"，挡不住"别人**已 staged**
   的东西被我的提交带走"（我两次踩中：一次是契约文档、一次是别人 staged 的测试文件）。
2. **验证结果只在"安静的树"上才有权威性。** 整树静态守卫在 103 个测试文件并行时会被饿死而**假红**
   （单独 54ms 全绿 / 并行 6167ms 失败）；与"同一拓扑上不该有两个动作"同源。发现假红时先问
   **"失败的环境干净吗"**，再问"产品坏了没有"。
3. **同一个判断写两遍就是两份真相。** 我自己写过一段不可达的重复判断（选择层已经判过"来源行不存在"）、
   `unionLimits` 的初值是另一个实例 —— 判据必须只有一个入口。
4. **小的靠类型，大的靠词表。** 我编造的理由码被 `tsc` 当场拦下（字符串层面）；语义扩张被封闭词表
   拦下（词表层面）。两者都要求"唯一真相只有一个地方"（`Record<ReasonCode, true>` / `REASON_CODE_REGISTRY`）。
5. **裁决的错误要与裁决一起可见。** 我在没读实现的情况下写过三条裁定（静默期"不加窗口"、渲染"需要
   独立模板"、"词表要改两处"），实施时全部被证伪 ⇒ 更正与原文并列留在契约里，而不是悄悄改掉。
6. **`docker` 环境的三个坑**（都写过脚本）：daemon 看不见宿主路径（构建上下文只能来自 runner 内部）；
   `docker exec` 不带 `-i` 时 heredoc 的 stdin **不接上**；runner 容器若用 `sleep 7200` 会在两小时
   后自杀并带走正在跑的门禁。
